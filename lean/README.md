# P2588: проверенный Lean-пакет (частичная формализация)

Версия: Lean 4.19.0. Mathlib: v4.19.0,
commit `c44e0c8ee63ca166450922a373c7409c5d26b00b`.

Исходные файлы были фактически скомпилированы в этой сессии. Это не полная
формальная проверка P2588: связь целочисленного сертификата с кардинальностью
множества выполнимых формул ещё не доказана внутри Lean.

## Что проверено

`P2588/Arithmetic.lean` и `P2588/Certificate.lean` используют только `Std`.
Lean проверяет все шесть шагов обращения ряда, шесть тождеств Адамара,
шесть тождеств квадратного корня, сборку итогового многочлена и:

```
coefficient S6 12 = 805717285720
coefficient S6 13 = 2381437338960
binom 60 12 = 1399358844975
binom 60 13 = 5166863427600
2 * coefficient S6 12 - binom 60 12 =  212075726465
2 * coefficient S6 13 - binom 60 13 = -403988749680
```

Также проверены сокращение дроби и первое строгое пересечение половины для
коэффициентов многочлена: все m=0,...,12 выше половины, m=13 ниже половины.
Данные H, E, R заданы явно и проверяются тождествами; два итоговых числа
получаются вычислением биномиального преобразования, а не отдельными аксиомами.

`#print axioms` для вычислительных теорем сообщает `does not depend on any axioms`.
Вычисления доказываются обычным `decide`, проверяемым ядром. `native_decide`,
`sorry`, пользовательские `axiom` и внешние вычислительные оракулы не используются.

`P2588/Model.lean` использует mathlib и формализует:

- шесть помеченных булевых переменных;
- 15 неупорядоченных пар переменных, представленных канонически как i<j;
- 60 клауз, по четыре знаковых варианта для каждой пары;
- формулы как `Finset Clause`, поэтому порядок и повторения исключены;
- исходный предикат выполнимости по 64 присваиваниям;
- сохранение выполнимости при удалении клауз;
- число всех m-элементных формул как `Nat.choose 60 m`;
- монотонность вероятности выполнимости по m, используя локальное неравенство LYM;
- вывод о первом пороге 13 **при явно указанных условиях** о двух кардинальностях.

В этих теоремах используются только стандартные основания Lean/mathlib:
`propext`, `Classical.choice`, `Quot.sound`. `sorryAx` в итоговых зависимостях нет.

## Точная граница проверки

`satCount m` в модели является кардинальностью настоящего семейства выполнимых
формул. `Certificate.coefficient S6 m` — коэффициент проверенного многочлена.
Следующие утверждения пока не доказаны в Lean:

```lean
(satCount 12 : Int) = Certificate.coefficient Certificate.S6 12
(satCount 13 : Int) = Certificate.coefficient Certificate.S6 13
```

Поэтому итоговая теорема называется `threshold13_of_enumeration_bridge`, и эти
равенства находятся в её списке гипотез. Они не спрятаны в определениях,
аксиомах или `sorry`. Вне Lean они подтверждены опубликованной теоремой и
независимым выполненным C++ DP из предыдущего пакета.

Для полного закрытия нужно формализовать соответствующий случай теоремы 4.7
об энумерации 2-SAT или связать проверенный точный подсчёт с `satCount`.
Запуск ядром только арифметического сертификата этой математической работы
не заменяет.

## Проверка без mathlib

`P2588Arithmetic.lean` объединяет два арифметических модуля в один файл:

```bash
lean P2588Arithmetic.lean
```

Нужны Lean 4.19.0 и его `Std`. Полная арифметическая проверка проходит без mathlib.
Этот файл не содержит модель и не утверждает безусловный порог для `satCount`.

## Проверка всего проекта

В обычном окружении с Elan:

```bash
lake update
lake exe cache get Mathlib/Combinatorics/SetFamily/LYM.lean Mathlib/Tactic/NormNum.lean Mathlib/Tactic/FinCases.lean Mathlib/Tactic/Positivity.lean Mathlib/Tactic/Linarith.lean
lake build
```

Команда `lake update` может автоматически запросить полный cache mathlib.
Чтобы скачать только нужные модули, выполните первую команду с
`MATHLIB_NO_CACHE_ON_UPDATE=1`.

Фактические выводы `#print axioms` сохранены в `certificate_build.log`,
`standalone_build.log` и `model_build.log`. Версии, особенности окружения и
способ запуска указаны в `verification_status.md`. Компилируемые доказательства
переносимы: исходники проекта не зависят от путей этой сессии.
Стандартная сборка `lake build` также завершилась с кодом 0; журнал `build.log`
включён вместе с точным `lake-manifest.json`.
